# バグ調査（2026-10-13）

対象：現行作業ツリーのERB/CSV。学校生活、学力購入、試験、部活動、ステータス表示の呼び出し経路を静的に確認。
ゲーム本体・セーブは変更していない。Emuera上の操作再現は未実施。下記の数値再現は現行ソースの整数計算をPythonで追跡した結果であり、エンジン実機テストとは区別する。

## 1. [P1] 主人公の能力購入画面で不正入力すると配列範囲外エラー

- 場所：ERB/SHOP_ショップ.ERB:2026（@ABL_UP_MASTER）
- 入力直後に `LOCAL = X:RESULT` を実行し、その後で `RESULT == 100` / `RESULT > 100` を判定している。負数のチェックもない。
- CSV/VariableSize.CSV の X は1000要素。
- 再現手順：能力アップで主人公を選び、能力選択画面に -1 または1000を入力。チェックより先に X:-1 / X:1000 を参照する。
- 影響：誤入力でゲームをエラー停止させる経路。実機入力は未実施。
- 修正方針：入力範囲と表示選択肢の有効性を検証してからXを参照する。

## 2. [P2] 初回取り込み後に購入した学力が再計算で消える

- 場所：ERB/SHOP_ショップ.ERB:2160-2161,2166-2168,2172-2174,2188-2190 / ERB/STAGE_学期進行・試験システム.ERB:627-631
- 購入はABL:88だけを増やし、保存用のCFLAG:88を増やしていない。CALC_ACADEMIC_LEVELはCFLAG:88が0の時だけ差分を取り込むため、一度購入分を取り込むと次の購入分を保持できない。
- 数値再現：学力素質50、経験0で学力51を初回再計算すると購入分1として保持される。その後1購入して52にしても、次の再計算で51に戻る。
- 影響：お金だけ消費し、追加購入分が学習状況表示や試験前の再計算で失われる。
- 修正方針：各購入経路で購入分をCFLAG:88へ加算。初回の既存セーブ取り込みとは別に管理する。

## 3. [P2] 学力購入が主人公の試験得点に反映されない

- 場所：ERB/STAGE_学期進行・試験システム.ERB:591-616（@GET_EXAM_SCORE）
- TAKE_EXAMとTAKE_MAKEUP_EXAMは学力を再計算してからGET_EXAM_SCOREを呼ぶが、得点式はABL:MASTER:98、EXP:MASTER:95、FLAG:210、ABL:MASTER:95のみを参照。ABL:MASTER:88とCFLAG:MASTER:88を参照しない。
- 数値再現：学力素質50、経験0、今学期勉強量0、知識技能0なら32点。購入で表示学力を増やしても同じ32点（通常試験の乱数・パートナーボーナスは固定して比較）。追試にも同じ問題がある。
- 影響：試験を助ける目的で学力を購入しても、主人公の得点は変わらない。学力は別途学力コンテストに使われるので、全用途で無効という意味ではない。
- 修正方針：購入分を得点式へ反映する、または購入機能の名称と説明を試験への効果がない仕様に合わせる。

## 4. [P2] 未購入でも経験減衰が購入ボーナスとして取り込まれる

- 場所：ERB/STAGE_学期進行・試験システム.ERB:484,627-631
- 「CFLAG:88 == 0」を初回移行判定として使うため、未購入のキャラは毎回移行判定に入る。試験後の経験減衰で算出学力が下がると、減衰前のABL:88との差が購入分として保存される。
- 数値再現：学力素質50、経験100、学力60、購入分0。経験を90に減衰させて再計算すると基礎学力59との差1が購入分となり、学力60が維持される。
- 影響：未購入キャラに恒久的な架空の購入ボーナスが付き、経験減衰後の学力計算がずれる。
- 修正方針：移行済みフラグを購入額と分離する。新規キャラで旧セーブ移行を走らせない。
