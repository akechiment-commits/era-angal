## 1. 作業対象ファイルの場所

### キャラごとに存在するファイル（3種）

```
ERB/CHAR/CHAR_NN_名前.ERB        ← ベースERB（行事・挨拶・エンディング等、約100スロ）
ERB/CHAR/CHAR_NN_名前_COM.ERB    ← COMERBメイン（936スロ、主作業）
CSV/CharaNN_名前.csv              ← 素質定義（キャラのパラメータ）
```

`NN` はキャラ番号（01〜71）。

### 参照資料ファイル（キャラ別）

優先度順に読む。

| 優先度 | ファイル | 場所 | 内容 |
|--------|----------|------|------|
| ★必須 | `{名前}_v3.txt` | `tools/v3prompt/` | キャラプロファイル＋会話パターン（最新版） |
| ★必須 | `{名前}.txt` | `tools/output/` | 原作セリフ全文（口調確認の一次資料） |
| ★必須 | `{名前}_分析.txt` | `tools/output/` | 語尾・口癖・一人称などの定量分析 |
| 状況次第 | `{名前}_転校生.txt` | `tools/output/` | 転校生（プレイヤー）への言及・呼びかけ方の抽出 |
| 参考程度 | `{名前}_関係性分析.txt` | `tools/output/` | 他キャラとの関係性（一対一口上では重要度低） |

例: さあやなら
```
tools/v3prompt/prompt_さあや_v3.txt
tools/output/さあや.txt
tools/output/さあや_分析.txt
tools/output/さあや_転校生.txt   ← 主人公への呼びかけを確認したいときに
```

### シナリオ参照（必要に応じて）

```
tools/scenarios/{番号}.txt        ← ゲーム内シナリオ原文
tools/story_ids.txt               ← シナリオIDとタイトル一覧
```

## 2. ステップ0: 設定.txt を作る（着手前に明智さんの確認を取る）

### やること

1. `tools/v3prompt/prompt_{名前}_v3.txt` と `tools/output/{名前}.txt`、
   `{名前}_分析.txt` を読んで原作セリフ・性格を把握する
   - ★**「自称」と「実態」を必ず分離する**（ましろセッションの学び）。
     キャラの自己卑下・ネタ設定（例:「私は馬鹿だ」）を額面どおり
     受け取らない。原作シナリオで裏取りし、実態と違うなら実態を採る。
     例: 日滝ましろは「自称馬鹿」だがシナリオ2704で問題集を全問正解、
     「運動も勉強もできる」と評される＝**勉強は苦手ではない**。
     v3の「思考単純」だけ見て勉強苦手と書くと手戻りになる（口上9箇所修正）。
2. **既存 CSV (`CSV/Chara{NN}_{名前}.csv`) の素質はいじらない**
   - 既に上流で決まっているので尊重する
   - 設定.txt には参考情報として既存素質一覧を記載するだけ
3. **新規に追加すべき素質候補があれば「別枠の追加提案」として書く**
   - 原則: **迷ったら付けない**（追加0個でも可）
   - 「キャラがその素質の人物に見えるか」で判断
   - `tools/talent_list.txt` を参照
   - 明智さんの判断で追加するか/しないかを決める
4. 紹介文（一人称・口調・性格核・人間関係・主人公呼称）をまとめる
5. 明智さんに見せて確認をもらう

### 設定.txt の保存先

```
tools/CHAR_NN_{名前}_設定.txt
```
（リポジトリ内に保存して git 管理対象にする）

## 3. ステップ1: ベースERBを埋める（約100スロ）

### 対象ファイル

```
ERB/CHAR/CHAR_NN_名前.ERB
```

### 書くセクション

| セクション | 内容 |
|-----------|------|
| `@CHAR_FIRST_DIALOG_NN` | 初回出会い |
| `@CHAR_REPEAT_DIALOG_NN` | 毎回挨拶 |
| `@CHAR_MORNING_GREETING_NN` | 朝の挨拶 |
| `@CHAR_REST_NN` | 休憩選択時の口上 |
| `@CHAR_LUNCH_NN` | 昼休み |
| `@CHAR_PARTNER_DIALOG_NN` | パートナー会話 |
| `@CHAR_SESSION_END_NN` | セッション終了 |
| `@CHAR_SPORTS_FESTIVAL_NN` | 体育祭 |
| `@CHAR_CULTURE_FESTIVAL_NN` | 文化祭 |
| `@CHAR_EXAM_BEFORE_NN` / `@CHAR_EXAM_RESULT_NN` | 試験前後 |
| `@ENDING_MARRIAGE_NN` / `@ENDING_GRADUATE_NN` | エンディング |
| `@CHAR_MILK_NN` | 搾乳 |
| `@CHAR_FUTA_EJAC_NN` | ふたなり射精 |

### 書き方の注意

- **ファイル読み書きはPythonで cp932 + CRLF**（Editツール使用禁止）
- ★`@CHAR_*` の出現回数は**ファイルによって違う**（ましろセッションの学び）。
  二重定義のファイルもあれば、各セクション1回だけのファイルもある
  （CHAR_67 日滝ましろは全セクション1回ずつだった）。**まず grep で
  出現回数を確認**し、1回なら1回目、2回定義なら2回目に書く:

```python
import re
matches = list(re.finditer(rf'@{セクション名}\b', content))
start = matches[-1].start()  # 最後の出現＝1回なら1回目、2回なら2回目で安全
```

### ステップ2: 純愛コミュ（約215スロ）

```

```

**★会話（COM301）は RAND:10 に拡張済み（2026-05-24）**:
- 最も使用頻度が高く個性が出るコマンドなので、恋人/親密/通常 各10＋初回1＝31枠
  （旧16枠から+15）。テンプレート・未実装45体・やこ(52)に適用済み。

**★会話には失敗分岐がある（COMF301で低確率の失敗判定）**:
- 失敗時は好感度・従順が下がる → 突き放し/機嫌を損ねた反応を書く。
- テンプレに失敗分岐（`IF TFLAG:18 == -1` → 恋人失敗1 + 失敗1）あり。必ず埋める。
- ※旧テンプレ由来のキャラは会話の失敗分岐を持たない個体が多い（失敗時に成功
  セリフが出る不整合）。新規実装時は会話の失敗も忘れず記入。

**蓬莱の薬（@HOURAI_KOJO）の注意**:
- COM_ERBファイル内に `@HOURAI_KOJO_NN` が **2箇所**ある

- 2箇所目: ファイル後半の大きなセクション
- 書き込み先: **1箇所目（早い方）** を使う

蓬莱4枠の構造（TFLAG:91で分岐）:

### ふたなり系13個の視点（修正1）

### ★視点（攻め／受け）判定の鉄則★（ほとりセッションで誤判あり・最重要）

- **最終判断は必ず該当COM直上の注釈を一次情報にする**。注釈は `;※` だけでなく
  **`;▼` で書かれているCOMもある**（深鳥ふみセッションの学び）。`;※` だけを
  grepすると `;▼` のみのCOMを取りこぼし、視点を逆に書く事故になる。
  **必ず `;※` と `;▼` の両方を拾うこと**。実際に全実装キャラで逆になっていた例:
  - **COM205 自慰見せつけ**（注釈 `;▼ プレイヤーがパートナーに自慰を見せる`）＝
    **キャラは見る側**（自分が自慰して見せるのは誤り）。
  - **COM67 足コキ**（注釈 `;▼ ふたなりのパートナーに対してプレイヤーが足コキする`）＝
    **キャラは受け**（自分が足コキするのは誤り）。
- **★女性器用コマンドは相手＝転校生になり得ない（COM61クンニと同型）★**:
  **COM203 クスコ**（女性器に挿入する診察器具）は、転校生が常に男性ゆえ
  **相手は助手か他の女子生徒、キャラが使う側・転校生は見る/命じる側**。
  「転校生にクスコを使う」「キャラ自身がクスコされる」はどちらも誤り
  （キャラ自身が受けるのは COM110 クスコの方）。全COM203注釈に
  「クスコは女性器用→相手は女子生徒・転校生不可」のクラリファイを追記済み。
- ★視点を直すときも**説明調にしない＝実演型で**（明智さん指摘）。「あなたが〜するの？」と
  状況を述べるのでなく、見ている眺め・身体感覚・相手や自分の反応を書く。
- コマンド名の「〜する／〜させる」は攻め受けの**当てにならない**
  （`手淫する`でもキャラが受け側のことがある）。
- 上表の矢印は「行為の方向」: **`P→K`＝プレイヤーがキャラに行う＝キャラは受け**／
  **`K→P`＝キャラがプレイヤーに行う＝キャラが攻め**。`P手淫`等の補記は「Pが手淫する側」の意。
- 実際に踏んだ誤り（ほとり）: **COM191 手淫する・COM192 パイズリする・COM196 ペニバン挿入**は
  いずれも※注釈に「プレイヤーがキャラ（ふたなり）を手淫／パイズリ／挿入する」とあり、
  **キャラは受け（される側）**。コマンド名だけ見て「キャラ攻め」と書くと誤り。
  → 正しく「キャラ攻め」なのは ※注釈に「キャラがプレイヤーに挿入／犯す」と明記された
    COM23逆レイプ・65助手を犯させる・90アナル愛撫させる・193/194正常位・後背位させる・
    204アナルに入れさせる・381セックスさせる（着衣）など。

### ★★プレイヤー（転校生）は常に男性＝性別変更不可★★（ひびきセッションの最重要学び）

- **このゲームにプレイヤー(転校生)の性別を変える手段はない。転校生は常に男性**。
- ゆえに「パートナー／ふたなりパートナー → **女性対象**」のコマンド（クンニ等）の相手は
  **転校生ではありえず、助手か他の女子（別の生徒）になる**。キャラが舐める/攻める側で、
  転校生は**見る／命じる側**として書く。
  - ★判定原則★：**転校生（男性）は「膣」も「胸」も持たない**。ゆえに
    (a) 膣への挿入を受ける側／(b) 胸で奉仕する側 になるコマンドは、相手が転校生では
    成立せず、**助手か他の女子が相手**になる（転校生は見る/命じる側）。
  - 該当コマンド（女性限定の完全リスト＝相手は助手/他の女子・転校生は見る/命じる側）:
    **COM61 クンニ**（キャラが女性器を舐める側）／**COM63 貝あわせ**（女性器同士）／
    **COM200 乳の揉み合い**（乳を合わせる女性同士）／**COM203 クスコ**（女性器用の診察器具＝
    キャラが女子生徒に使う側）／**COM65 助手を犯させる**（相手＝助手）／
    **COM192 パイズリする**（胸でふたなりキャラのペニスを奉仕＝胸のない転校生は不可・giver＝助手/他の女子）／
    **COM23 逆レイプ**（ふたなりキャラが「膣」に挿入＝膣のない転校生は対象不可・相手＝助手/他の女子）。
    → これら全COMの注釈に「転校生は常に男性→相手は助手か他の女子」のクラリファイを追記済み
    （COM200は元々注釈ゼロだったため新設）。
    ※対して**アナルへの挿入**（COM193/194正常位・後背位させる／COM204／COM195騎乗位する等、
      注釈に「（女性）」がないもの）は**男性転校生のアナル**で成立するので転校生が相手でよい
      （手順書の「挿入系は男性転校生のアナルへ読み替え」を適用）。「（女性）」「膣」「胸/パイズリ」
      が明記されたものだけが女性限定。
  - ★特にCOM61クンニは要注意：クンニは女性器への行為なので、相手が男性の転校生はありえない。
    「転校生に舐められて感じる（キャラ受け）」「転校生のアレを舐める（＝フェラの誤り）」は
    **どちらも誤り**。正しくは「キャラが助手/他の女子を舐める・転校生は見ている」。
  - ※注釈に「（女性）プレイヤー」とある場合も、実際の転校生は男性。挿入系（COM23逆レイプ等で
    「プレイヤーが挿入される側」）は男性転校生のアナルへ、と読み替える（クンニ等の女性器前提の
    行為だけは相手＝別の女子に置き換わる）。
- **2026-05-25 監査結果**：実装済み多数のキャラで女性限定コマンドが「転校生を相手」にしていた
  （COM61クンニ／COM63貝あわせ5体／COM200乳の揉み合い13体）。全実装キャラを女性同士・転校生は
  見る側に修正済み。今後の新規実装では必ず上記を意識する。全該当COMの注釈にクラリファイ済み。

### ★セリフは「行為の説明」でなく「実演」で書く★（クンニ改稿セッションの学び）
- **NG（説明調）**：「この子を舐めればいいんですね」「転校生が見てる前でこの娘を舐めるっち」
  など、これから何をするかをナレーションする型。状況はプレイヤーに伝わっているので冗長。
- **OK（実演型）**：舐めている最中そのものを描く。次の3要素を各キャラの口調で混ぜる。
  1. **ぺろぺろ感**＝舌の擬音（れろ／ちゅ／ぴちゃ／ちゅぱ／ぺろ）
  2. **行為への感想・どう思うか**＝味／濡れ具合／温かさ（しょっぱい／とろとろ／夢中になっちゃう）
  3. **相手の反応へのコメント**（ビクッてした／感じてる／可愛い声／もうこんなに濡れて）
- 既に最中のセリフを言えているキャラは、**冒頭の説明文を削るだけ**でよい。
- COM61に限らず**口上全般**に効く原則。状況説明より、行為中の身体感覚・感想・反応を言わせる。
- 例外：説明的でもそれ自体がキャラ性になる場合のみ可（例：20しずく＝不器用さ/パパ呼びの感想型）。

### @CHAR_ORGASM の150スロ構造

```
五重絶頂（TFLAG:710 >= 5）: 24スロ
  全部位最強★（NOWEX全部位>=9）: 恋人3 + 通常3
  最強（>=9）: 恋人3 + 通常3
  強（>=2）: 恋人3 + 通常3
  通常: 恋人3 + 通常3

複絶頂（TFLAG:710 >= 2）: 36スロ
  膣含む: 最強/強/通常 × (恋人3 + 通常3) = 18
  膣なし: 最強/強/通常 × (恋人3 + 通常3) = 18

単絶頂: 90スロ
  V/A/C/B/M 各部位 × 3強度 × 6スロ（恋人3 + 通常3）= 18
  全5部位で 90
```

### ★絶頂は「強度＝崩壊度」の勾配で書く（v23の最重要ノウハウ）

絶頂を一律に喘がせない。強度ごとにキャラ性の残り具合を変える。

- **通常絶頂** = そのキャラの素のテンションを残す。「普通に気持ちいい」。
  恋人時は幸福・余裕。例（やこ＝傲慢）「ふん、いったわよ。今のは及第点ね」/
  恋人「ふふ、あんたとだと気持ちいいわね♪」。**崩れさせない**。
- **強絶頂** = 余裕が崩れ始める。**最強/複絶頂/五重絶頂** = 強すぎる快感で崩壊
  （語尾・言葉が崩れ、強すぎる快感で錯乱した様子を出す）。
  ※**「錯乱した様子」さえ出れば人称は不問**。人称揺らぎ（「わた、し」等）は
   演出の一手段にすぎず**必須ではない**（明智さん指示）。やるなら原作一人称ベースで。
- **★三点リーダ（……）の数＝崩壊度の指標として使う★**
  通常tier≒0個 / 強tier≒2個 / 最強・複・五重≒3個以上。
  通常絶頂に……を多用すると、傲慢・強気キャラまでか弱く見える（明智さん指摘）。
- キス（M）絶頂は唇・息で（のど・口いっぱいはイラマ向けでNG）。
- **★部位語の直接／婉曲はキャラ性・素質で選ぶ★**（ほとりセッションの学び）
  「快感に素直」「自慰しやすい」「奔放」系は**直接語**（おまんこ／クリ／アナル／乳首）で
  素直に感じさせるとハマる。「プライド高い」「大人しい」「初心」系は**婉曲寄り**（あそこ等）。
  婉曲の「奥」「胸」連発は単調なので素質に合わなければ避ける
  （ほとりは当初「奥／胸」で書いたが素質に合わず直接語へ全面改稿）。

## 7. ファイルの読み書き

### 必須: Python で cp932 + CRLF

```python
# 読み込み
with open('ERB/CHAR/CHAR_NN_名前_COM.ERB', 'rb') as f:
    content = f.read().decode('cp932')

# 書き込み
with open('ERB/CHAR/CHAR_NN_名前_COM.ERB', 'wb') as f:
    f.write(content.encode('cp932'))
```

- **Edit ツール使用禁止**（UTF-8で上書きされて文字化けする）
- 波線は `〜`（U+301C）推奨。ただし `〜`(U+301C) も `～`(U+FF5E) も
  cp932 では同一バイト `0x8160` になり機能差はない（既存ファイルは 0x8160）。
  半角 `~`(U+007E/0x7E) だけは別物なので使わない。
