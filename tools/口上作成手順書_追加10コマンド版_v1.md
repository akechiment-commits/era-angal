# 追加10コマンド口上 作成・実装手順書 v1

更新日：2026-08-02  
対象：COM60 / 62 / 76 / 78 / 79 / 84 / 86 / 202 / 258 / 318  
基準実装：三善かなえ（CHAR01）、北川ゆき（CHAR02）、小野ちよ（CHAR03）

## 1. この資料の目的

この資料は、既存キャラクターに不足している10コマンドの口上を、キャラクター本人が生きていると感じられる品質で追加するための専用手順書である。

目標は「状況に合う文章を60行埋めること」ではない。各キャラクターが、その場で何を見て、どう受け取り、何を隠そうとし、どこで平静を失うかを台詞にすることが目標である。

1キャラクターあたりの完成条件は次のとおり。

- 10コマンドすべてに口上がある。
- 各コマンドに恋慕時3種、非恋慕時3種がある。
- 合計60本が、同じ人物の言い換えではなく、そのキャラクターの複数の面を見せている。
- コマンドの参加者、身体配置、行為の向きが実装と一致している。
- ERBの文字コードと改行を壊さず、回帰チェックを通過している。
- 1人ずつ作成・確認し、承認されてから次のキャラクターへ進む。

本書は追加10コマンド専用であり、総合的な口上作成規則は既存資料も併読すること。

## 2. 作業前に読む資料

### 2.1 全体ルール

最初に次の3ファイルを読む。

1. `tools/引き継ぎ書_v23.txt`
2. `tools/口上作成手順書.md`
3. `tools/口上加筆_整合作業ガイド.md`

既読のつもりでも、別セッションから再開した場合や判断基準に迷いが出た場合は読み直す。検索結果の数行だけで代用しない。

### 2.2 キャラクター把握用資料

対象キャラクターごとに、原則として次の順番で全文を読む。

1. `tools/v3prompt/prompt_<キャラ名>_v3.txt`
2. `tools/CHAR_NN_<キャラ名>_設定.txt`
3. `tools/CHAR_NN_<キャラ名>_整合記録.txt`
4. `tools/output/<キャラ名>.txt`
5. `tools/output/<キャラ名>_転校生.txt`
6. 存在すれば `tools/<キャラ名>_転校生.txt`
7. 存在すれば `tools/output/<キャラ名>_関係性分析.txt`
8. `ERB/CHAR/CHAR_NN_<キャラ名>_COM.ERB` の既存口上

`tools/output/<キャラ名>.txt` は、キャラクター本人の台詞を掴むための最重要資料である。長いファイルが途中で省略された場合は、範囲を分けて最後まで読む。冒頭の数十行や検索ヒットだけで人物像を決めない。

既存ERBでは、次の場面を優先して確認する。

- 平常時と恋慕時の一人称、呼称、語尾
- 驚き、羞恥、怒り、恐怖、嫉妬の出し方
- 強い快感時に文章がどう崩れるか
- 相手を気遣う時と、自分の欲求を出す時の差
- 下品な単語を直言する人物か、婉曲にする人物か
- その人物特有の価値判断、弱点、習慣、比喩

### 2.3 行為と参加者を確認する資料

各コマンドの意味は必ず `ERB/COMF/COMF<ID>.ERB` で確認する。

コマンド名や過去の記憶から参加者を推測してはいけない。参加者、性別条件、前提コマンド、誰が誰に触れているかはCOMFの実装を正とする。

資料同士に食い違いがある場合の優先順位は次のとおり。

1. 身体配置と参加者：`ERB/COMF/COMF<ID>.ERB`
2. キャラクターの口調と事実：原作台詞出力、整合記録、既存口上
3. 人物像の整理：V3 prompt
4. 素早い参照：設定ファイル

## 3. 書き始める前のキャラクター把握メモ

60本を書き始める前に、最低限、次を自分の言葉で整理する。

- 一人称、転校生の呼び方、同年代女性への呼び方
- 平常時の文の長さ、敬語、口癖、記号の使い方
- 照れた時に黙るか、誤魔化すか、怒るか、饒舌になるか
- 怖い時に助けを求めるか、強がるか、固まるか
- 恋慕すると素直になるか、独占的になるか、依存を隠すか
- 快感が弱い時と強い時で、台詞がどう崩れるか
- 身体への自信やコンプレックス
- 世話焼き、競争心、食、仕事、趣味など、その人物らしい判断軸
- 既存口上で避けるべきと判明している誤解や混入口調
- 10コマンドのどこで、どの人物面を見せるか

最後の項目が重要である。好きな食べ物や決め台詞を全コマンドに貼るのではなく、世話焼き、意地、弱さ、嫉妬、好奇心、信頼などを10コマンドへ分散させる。

可能なら、名前を消しても誰の台詞か推測できる状態を目指す。

### 4.1 COM60 助手にキスさせる

「助手」という語があるため、誰が誰へキスするかを既存の呼称初期化とCOMFで確認する。承認済み口上では、対象キャラが助手へキスし、転校生がそれを見る構図や嫉妬が使われている。

単に「キスした」「唇が柔らかい」で終わらせず、対象キャラが視線を誰に向けるか、恋人への後ろめたさや対抗心、助手への戸惑いを出す。

### 4.2 COM62 ダブル素股

対象キャラ、助手、PLAYERの三人がいる。助手の呼称を得て、二人の脚の動き、息を合わせる難しさ、競争や気遣いをキャラクターらしく処理する。

身体の実況だけではなく、「相手に負けたくない」「相手を気遣う」「三人でいることを恥じる」など、その人物の人間関係の癖を反応へ混ぜる。

### 4.3 COM76 双頭バイブ

助手調教専用で、対象キャラと女性助手の二人だけが行為当事者である。転校生の呼称、先輩、お兄ちゃんなどを絶対に出さない。

片側の動きや震えがもう片側へ伝わる相互作用が核になる。恋慕時の好意も女性パートナーへ向ける。穏やかな会話だけで終えず、相手が動くと自分にも刺激が返るため、台詞が途中で崩れる瞬間を作る。

### 4.4 COM78 母乳飲み

PLAYERが口で直接飲む。胸を吸われる感覚、与えることへの羞恥や慈愛、相手が飲む姿をどう受け止めるかが中心になる。

人物によって、世話焼き、支配欲、母性的な満足、身体を見られる不安など重点を変える。味や量だけを説明しない。

### 4.5 COM79 乳搾り

PLAYERが手で搾る。COM78とは、口ではなく手、飲むのではなく搾り出して溜める、という違いを明確にする。

手加減への要求、量を見られる羞恥、作業のように扱われる反発、搾られる感覚を人物らしく反応させる。

### 4.6 COM84 Gスポット刺激

強い快感によって平静が崩れる場面である。特に恋慕時も、愛情を説明する余裕より、信頼している相手に弱点を突かれて制御を失う様子を優先する。

悪い例：

> 「あなたを愛しています。この刺激もあなたとなら受け入れられます」

方向性の良い例：

> 「そこ、だめ……っ、止め――あっ、止めないで……！」

文を短くし、言い直し、途切れ、矛盾した要求、呼びかけを使う。ただし、全員を同じ喘ぎ方にしてはいけない。普段の理性や語尾が、どのように壊れるかを書く。

### 4.7 COM86 強制放尿

快感だけでなく、羞恥、恐怖、見捨てられる不安、尊厳を保とうとする反応が中心になる。ただし「見ないで」「嫌いにならないで」「終わったら抱きしめて」「自分で片づけるから向こうを向いて」は、誰にでも成立する安易な終着点である。複数キャラへ繰り返してはならない。

まず、その人物が制御喪失を何として受け取るかを決める。失敗、敗北、予定外、身体からの裏切り、物語の空白、役割の逆転、怒るべき越境など、解釈の入口をキャラごとに変える。台詞は後始末の申し出ではなく、その解釈から発生する行動や要求へ着地させる。

恋慕時も「好きだから平気」にはしない。好きな相手だからこそ見られたくない、終わった後に安心を求める、といった相反する気持ちを使える。

### 4.8 COM202 乳首合わせ

助手調教専用で、対象キャラと女性助手の二人だけが当事者である。COM76と同様、転校生を一切出さない。

身体の近さ、顔の近さ、胸への自信や劣等感、女性同士だからこその比較や照れを使う。恋慕時の親密さは女性パートナーとの関係として書く。

### 4.9 COM258 助手顔面騎乗

最も身体配置を誤りやすいコマンドである。

- 対象キャラ：PLAYERの上で騎乗位を続け、挿入されている。
- 助手：PLAYERの顔へ跨り、クンニさせている。
- PLAYER：下半身では対象キャラ、口では助手を相手にしている。

対象キャラは見物しているのではない。助手が動くことによるPLAYERの身体の揺れ、下からの突き上げ、膣内の擦れ、脚の力が抜ける感覚などに反応する。

特に恋慕時は、助手を見ながら冷静に感想を述べる長台詞を避ける。挿入刺激で本人が感じており、視線と身体の両方を制御できない状態を、途切れた台詞で出す。

### 4.10 COM318 頭を撫でてもらう

名称だけでは視点を誤解しやすいが、口上では対象キャラがPLAYERの頭を撫でる側である。

非性的なコマンドなので、無理に喘ぎや短文へ寄せない。その人物の世話の焼き方、慰め方、距離感、成長、立場の逆転を見せる貴重な枠として使う。

## 5. 1コマンド6本の設計

各コマンドは次の構造にする。

```erb
IF SELECTCOM == <COM番号>
	A = RAND:3
	IF TALENT:TARGET:85
		IF A == 0
			PRINTFORMW 「恋慕1」
		ELSEIF A == 1
			PRINTFORMW 「恋慕2」
		ELSE
			PRINTFORMW 「恋慕3」
		ENDIF
	ELSE
		IF A == 0
			PRINTFORMW 「非恋慕1」
		ELSEIF A == 1
			PRINTFORMW 「非恋慕2」
		ELSE
			PRINTFORMW 「非恋慕3」
		ENDIF
	ENDIF
ENDIF
```

今回の条件は `TALENT:TARGET:85` である。古いテンプレートに別の恋人・恋慕番号があっても流用しない。

### 5.1 恋慕と非恋慕の差

同じ台詞の末尾へ「好き」「嫌い」を足すだけでは不十分である。

恋慕時には、次のような関係の蓄積を使う。

- 信頼して弱みを預ける
- 嫉妬や独占欲が漏れる
- 相手だから許したいのに、身体が追いつかない
- 終わった後の約束や安心を求める
- 普段は言えない欲求が、快感で漏れる

非恋慕時には、単純な拒絶以外にも次を使う。

- 驚いて確認する
- 強がりや冗談で体面を保つ
- 条件や手加減を交渉する
- 恥じながら相手を気遣う
- 自分でも理解できない反応に戸惑う
- 怒る、黙る、責任を取ろうとする

### 5.2 台詞を「実況」から「反応」へ変える

弱い台詞は、画面で起きていることをそのまま説明する。

> 「胸を揉まれています。母乳が出ています」

口上に必要なのは、出来事に対する人物固有の解釈と選択である。

> 「量は数えないで。そういう数字まで知られるの、落ち着かないの」

基本の流れは次のとおり。

1. 何かを感じる、見る、気づく。
2. その人物らしい価値判断や感情が動く。
3. 隠す、求める、拒む、気遣う、張り合うなどの行動が台詞に出る。

すべてを一文で説明する必要はない。むしろ強い快感中は、2と3が言葉になり切らず漏れるほうが自然である。

### 5.3 強い刺激中の文章

Gスポット刺激、双頭バイブ、助手顔面騎乗などでは、整った長文を続けない。

優先順位は次のとおり。

1. 今まさに起きている身体反応
2. 相手への感情や呼びかけ
3. キャラクター固有の比喩や口癖

使える崩し方は、息継ぎ、言い直し、省略、矛盾、濁音、語尾の消失、同じ呼称の反復などである。ただし喘ぎ声だけで人物差を消してはいけない。

冷静な人物も別人のように騒がせるのではなく、「普段なら保てる制御がどこから崩れるか」を書く。饒舌な人物でも、強い刺激の最中に状況を分析し続けさせない。

## 6. 助手の呼称と専用コマンド

助手が台詞上の相手になるCOM62、76、202、258では、各ブロック内で助手の呼称へ切り替える。

```erb
CALL AITE_YOBI, <キャラ番号>, ASSI
LOCALS '= @"%RESULTS%"
```

`<キャラ番号>` は対象キャラクターのCHAR番号である。モード指定ではない。

対象ファイル冒頭では通常、PLAYERに対する呼称が `LOCALS` に入っている。三人行為や助手専用行為で誰を `%LOCALS%` として呼んでいるか、ブロックごとに確認する。

特に次を機械的にも確認する。

- COM76に転校生の固有呼称がない。
- COM202に転校生の固有呼称がない。
- COM76と202の恋慕は、女性助手へ向いている。
- COM62と258では助手の存在が台詞から消えていない。

## 7. 品質を落とす典型例

次の状態があれば書き直す。

- コマンド名を文章へ直しただけになっている。
- 10コマンドすべてで同じ口癖、食べ物、趣味の比喩を使っている。
- 恋慕3本がすべて長い愛の告白になっている。
- 非恋慕3本がすべて「やめて」「恥ずかしい」だけである。
- 羞恥、不安、拒絶、自己否定だけで人物差を作り、全員がややネガティブな反応へ寄っている。
- キャラらしさを一つの口癖、部活、趣味の比喩だけで表し、全10コマンドへ繰り返している。
- 強い快感中も句読点の整った長文で冷静に解説している。
- 全キャラが同じ喘ぎ、同じ語尾、同じ拒絶をする。
- キャラクターらしさを出すため、別キャラの象徴語や口調を借りている。
- 行為の主語や参加者が曖昧なまま書かれている。
- COM78と79の違いがない。
- COM76と202へ転校生を登場させている。
- COM258で対象キャラ自身の挿入感覚がない。
- COM318で対象キャラが撫でられている。
- メタ説明、UI、コマンド名、作成者の注釈が台詞へ入っている。

## 8. 作成の進め方

### 8.1 1人ずつ作る

全キャラクター分を一括生成しない。次の単位で進める。

1. 対象キャラの資料を全文確認する。
2. 10コマンド60本を作る。
3. 自己レビューで参加者と口調を直す。
4. ゲームへ実装して検証する。
5. ユーザーに1人分を確認してもらう。
6. 承認または修正完了後に、次のキャラへ進む。

対象人数は思い込みで決めず、実ファイルと監査結果から確認する。既に承認されたキャラクターは、後続への指摘を理由に無断で書き換えない。

### 8.2 60本を一気に似せない

最初に10コマンドの感情役割を割り振ると、重複を防ぎやすい。

例：

- COM60：嫉妬や対人距離
- COM62：競争心や協調性
- COM76：女性パートナーへの信頼
- COM78：与えることへの感情
- COM79：身体への自信や羞恥
- COM84：理性の崩れ方
- COM86：尊厳と不安
- COM202：同性との距離感
- COM258：複雑な状況での独占欲と制御喪失
- COM318：世話の焼き方、成長、優しさ

これは固定配役ではない。キャラクター資料に合わせて入れ替える。

## 9. CP932を壊さない実装方法

キャラクターERBはCP932・CRLFである。通常のUTF-8パッチで直接編集しない。

UTF-8の生成スクリプトを `tools/` に作り、そのスクリプトでERBを読み書きする。承認済みの参考実装は次の3本。

- `tools/add_trial_missing_koujo_kanae.py`
- `tools/add_trial_missing_koujo_yuki.py`
- `tools/add_trial_missing_koujo_chiyo.py`

生成スクリプトの必須要件は次のとおり。

- `read_bytes().decode("cp932")` で読む。
- 追加ブロックはUTF-8のPythonソース内へ置く。
- 書き込み前にLFをCRLFへ変換する。
- `encode("cp932")` で書く。
- 開始・終了マーカーを付ける。
- マーカーが既にあれば置換し、なければ指定アンカー前へ挿入する。
- 同じスクリプトを2回実行しても重複しない、冪等な作りにする。

現行実装では、次のアンカー直前へ追加している。

```text
;==============================================================
; 処女喪失時  @CHAR_VIRGIN_<キャラ番号>
```

生成スクリプト内ではアンカーのCRLFも明示する。

## 10. 実装後の検証

### 10.1 構造チェック

追加ブロックについて、最低限次を確認する。

- `IF SELECTCOM ==` が10個ある。
- 対象COM番号が60、62、76、78、79、84、86、202、258、318である。
- `PRINTFORMW` が合計60個ある。
- 各COMに `PRINTFORMW` が6個ある。
- `IF TALENT:TARGET:85` が10個ある。
- `IF` と `ENDIF` の数が対応している。
- COM62、76、202、258に正しい助手呼称の初期化がある。
- COM76、202に転校生の呼称がない。

### 10.2 文字コードと冪等性

- 完成ERBをCP932として再読込できる。
- CP932へ再エンコードできない文字がない。
- 改行がCRLFで統一され、裸のLFがない。
- 生成スクリプト実行前後のハッシュを取り、2回目で変化しない。

機種依存しやすいダッシュ、引用符、装飾記号を新しく使う場合は、必ずCP932変換を確認する。

### 10.3 リポジトリの検証

```powershell
python tools/run_regression_checks.py
python tools/audit_koujo_slots.py <キャラ番号>
```

期待結果は、回帰チェック8/8通過、対象キャラの不足・空口上なしである。

この作業では `npm test` は使わない。定義されたnpmテストではなく、上記の専用Python検証を使う。

CP932・CRLFのERBに対する一般的な `git diff --check` は、CRを空白エラーのように大量表示する場合がある。専用の文字コード、改行、構造チェックを合否判定の中心にする。

### 10.4 内容チェック

機械検証の後、各台詞を次の質問で読み直す。

1. 誰が誰に何をしているか、COMFと一致しているか。
2. キャラ名を消しても、その人物らしい感情の運びがあるか。
3. 恋慕と非恋慕で、関係性が本当に変わっているか。
4. 3パターンが同じ反応の言い換えになっていないか。
5. 強い刺激中に説明しすぎていないか。
6. 既存口上の一人称、呼称、語尾、語彙に反していないか。
7. 他キャラの象徴語や口癖が混ざっていないか。
8. COM76、202、258、318の視点を誤っていないか。
9. 同じコマンドを既作成キャラと横並びにし、文頭、感情の転換点、最後の要求が重複していないか。
10. 文字列が違っていても、「相手が上達したと指摘する→身体が反応する→続行を頼む」のように、観察・反応・結論の順序が同じなら重複として書き直す。n-gramや一致文字数は補助にすぎず、発想の被りを合格扱いしない。

## 11. 承認済み実装の使い分け

次のファイルの追加ブロックを参考にできる。

- `ERB/CHAR/CHAR_01_三善かなえ_COM.ERB`
- `ERB/CHAR/CHAR_02_北川ゆき_COM.ERB`
- `ERB/CHAR/CHAR_03_小野ちよ_COM.ERB`

使い分けの目安は次のとおり。

- かなえ：キャラクター固有の価値観を各行為へ接続する参考
- ゆき：関係性、嫉妬、助手を含む複数人場面の参考
- ちよ：Gスポット刺激と助手顔面騎乗で、快感により台詞が崩れる強さの現行基準

既存行を名前だけ置換して流用してはいけない。参考にするのは文章そのものではなく、「そのキャラクターの性格が、その場の反応へどう変換されているか」である。
