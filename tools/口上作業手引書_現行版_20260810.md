> ## 最優先・毎キャラ着手時に必ず再確認：COM130／131／132の視点
>
> コマンド名は「目隠しされる」「拘束される」「口枷される」だが、実際の口上視点は逆。**キャラがプレイヤーに目隠し・拘束・口枷を施し、プレイヤーがされる側**である。キャラ自身が目隠しされる／縛られる／口枷を付けられる台詞は誤り。既存A=0、新規RAND分岐、恋人・通常の全行で確認すること。作業開始時は必ず`ERB/CHAR/CHAR_NN_名前_COM.ERB`のCOM130〜132直上にある`;▼【視点】`注釈と、この警告を読み直す。

> 同じ確認を、COM130〜132以外の視点要注意COMにも適用する。**コマンド名や「する／させる／される」だけで主体を決めない。** 直上の`;▼【視点】`、`COMF<ID>.ERB`、助手の有無を照合し、キャラ・プレイヤー・助手の三者を先に書き出してから台詞を書く。過去に混同が出た代表例は、COM4/67/191/380（プレイヤー奉仕・キャラ受け）、COM61/63/160/188/189/192/193/194/195/196/200/203/381（女性助手・他女子が相手）、COM35/37/38/39/66/68/80/201（奉仕方向・人数）、COM56/65/205/258/318（助手・観客・撫でる側の取り違え）である。

## 1. 今やっている作業

キャラクターごとのCOM口上を、次の二段階で整備しています。

1. 追加10コマンドを実装する
2. 既存口上のうちRAND分岐がないコマンドを、元口上を残した3分岐へ拡張する

RAND:3化の基本形は次のとおりです。

```erb
IF SELECTCOM == N
    A = RAND:3
    IF TALENT:TARGET:153
        IF A == 0
            ; 既存の恋人時口上
        ELSEIF A == 1
            ; 新規口上1
        ELSE
            ; 新規口上2
        ENDIF
    ELSE
        IF A == 0
            ; 既存の通常口上
        ELSEIF A == 1
            ; 新規口上1
        ELSE
            ; 新規口上2
        ENDIF
    ENDIF
ENDIF
```

重要なのは、A=1/A=2を元台詞の語尾違いにしないことです。同じコマンドでも、反応の入口・身体感覚・感情の着地点を変えます。説明調は最小限にし、行為中の声、息、戸惑い、相手への反応を中心に書きます。

## 5. RAND:3化の実装方法

### 5.1 通常の2分岐コマンド

恋人／通常の両方を、それぞれA=0/A=1/A=2にします。元の口上は必ずA=0へ残します。

### 5.2 装着・解除のトグルコマンド

COM11、13、14、15、16、17のように`TEQUIP`がある場合は、装着側と解除側を別々に3分岐化します。

```erb
IF SELECTCOM == 11
    A = RAND:3
    IF TEQUIP:11
        IF TALENT:TARGET:153
            IF A == 0
                ; 元の装着・恋人
            ELSEIF A == 1
                ; 新規装着・恋人1
            ELSE
                ; 新規装着・恋人2
            ENDIF
        ELSE
            ; 通常側も同じ形
        ENDIF
    ELSE
        ; 解除側も恋人／通常を各3分岐
    ENDIF
ENDIF
```

### 5.3 独自280〜284／410〜414

レンジ式の`IF SELECTCOM == 280`〜`ELSEIF SELECTCOM == 284`は、各分岐の場面説明を残したまま、恋人／通常の台詞部分だけをRAND:3化します。410〜414のデート系も同じです。

場面の地の文を3回複製して水増ししないこと。RANDで変えるのは、ななのその場の言動と感情です。

## 6. 台詞の品質基準

### 6.1 実演型にする

NG：

```text
「これから○○をします」
「○○されているので恥ずかしいです」
```

OK：

- その瞬間の声、息、言いよどみ
- 触れられた場所や身体の反応
- 相手がどう反応したかへの返事
- そこから生まれる感情の変化

RAND:3の3枠は、説明調を最大1枠までにし、残り2枠は実演型にします。恋人／通常の固定2分岐も、両方とも実演型にします。

### 6.2 ななの声

- 一人称「あたし」
- 主人公「転校生くん」
- `ですよーっ！`、`ですねーっ！`、`ますーっ！`、`ファイトーっ！`
- 嬉しい場面は`♪`や`☆`
- 驚きは`うひゃっ`、泣きや怖さは`うわぁんっ`、明るい笑いは`あはは`
- 元気な表面だけで押し切らず、初心ゆえの驚き・照れ・足が止まる感じを混ぜる
- 失敗や動揺のあと、無理に大人びず「ファイト」で立て直そうとする

### 6.3 女子相手COM

女子相手のCOMは、呼称マクロ`%LOCALS%`をそのまま使って相手を呼びます。`%LOCALS%`にはキャラクター固有の呼称と敬称（さん／ちゃん／先輩など）が含まれるため、後ろに敬称を付け足しません。転校生くんを観客として強調したり、「女の子同士なのに」「攻める側」などの行為解説を入れたりもしません。

視点が不明なコマンドは、作業前に`tools/口上作成手順書.md`の「混同しやすいCOM番号」と、COMブロック上部の視点コメントを確認します。

## 7. CP932・CRLFを壊さない実装

ERB/CSVはCP932、改行はCRLFです。UTF-8で直接上書きしないこと。

```python
from pathlib import Path

path = Path("ERB/CHAR/CHAR_NN_名前_COM.ERB")
text = path.read_bytes().decode("cp932")

# 先にエンコードできることを確認する
data = text.encode("cp932")
path.write_bytes(data)
```

新しい口上にCP932非対応文字（長いダッシュ等）を入れないこと。大きな書き換えでは、生成スクリプトにマーカーを付けて冪等性を確保します。

```text
;=== CHAR29 MISSING COMMAND START ===
...
;=== CHAR29 MISSING COMMAND END ===
```

実行済みスクリプトをもう一度走らせて二重挿入しないよう、マーカーがあれば停止または既存範囲を置換する設計にします。

```powershell
p = Path(r"ERB/CHAR/CHAR_NN_名前_COM.ERB")
b = p.read_bytes()
s = b.decode("cp932")
print("IF", len(re.findall(r"(?m)^\\s*IF(?:\\s|$)", s)))
print("ENDIF", len(re.findall(r"(?m)^\\s*ENDIF\\s*$", s)))
print("CRLF", b.count(b"\\r\\n"), "LF", b.count(b"\\n"))

```
