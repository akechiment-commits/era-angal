## プロジェクトの本質
あんさんぶるガールズ!!ベース ERA adult RPG 向け、
全71キャラの口上ERB（Shift-JIS + CRLF）生成。
全キャラ20歳以上の成人設定。
ベースERB 52箇所 + COM.ERB 922箇所 = 974箇所/キャラ。

**このプロジェクトが求めているのは「大量生産」ではなく
「キャラ一人一人が別人として立ち上がる」こと。**
量はこなさなきゃいけないが、質を犠牲にした瞬間ユーザーに見抜かれる。

**1キャラ1セッションで完結させる。**

===============================================================
■ Claudeが陥りがちな失敗パターン（最重要）
===============================================================

### パターンA: キャラの「構造」化

前のキャラで書いたセリフの形（喘ぎ音の並び、3軸の類型、
部位ごとの反応語彙）をそのまま次のキャラに適用する。
セリフ単位では別物に見えても、**リズムとパターンが同じ**。

本質的な原因はClaudeが省エネしたくなるから。150箇所の
絶頂セリフをキャラ固有に書ききるのはしんどい。前キャラの
テンプレに流れるほうが楽。

対策: **前キャラと「質的に」違うキャラを書く、という覚悟を
都度持つ。** 弾くべきは「そのキャラがするはずのない反応」で、
これはワード単位では判定できない。キャラの身体性・職業性・
精神性を都度想起するしかない。

### パターンB: 手癖の固定化

キャラ固有の要素を強調しようとして、**そのキャラの口癖や
特徴的な喘ぎ音・笑い方を1セリフに詰め込みすぎる**。結果として
「どもりキャラ」「口癖連発キャラ」のような奇妙な印象になる。

本質的な原因は「キャラらしさを出さなきゃ」という義務感。
特徴的な音を毎行入れれば個性が出ると錯覚してしまう。

対策: **特徴的な表現は"効くときに効かせる"**。
常用すると陳腐化する。セクション全体で見て、濃淡のある
配分になっているか確認する。キャラによって何が手癖化
しやすいかは違うので、数値目安を機械的に置くのは不適切。
書き終えたセクションを眺めて、同じ要素が並んでないかを
都度目視確認するのが唯一の対策。

### パターンC: キャラの状態とセリフの質感のミスマッチ

同じキャラでも、**どのコマンドを受けている状態か**で
セリフの質感は変わる。状態を誤ると構図的におかしくなる。

状態のグラデーション例:
- **攻めている/余裕がある**: 支配的表現、からかい、観察者目線
- **受けているが余裕あり**: 虚勢、照れ隠し、評価者目線
- **受けていて切迫**: 抵抗、葛藤、素の露出の兆し
- **完全に崩壊**: 固有名詞の混濁、防衛線の瓦解、内的メタファーの崩れ

**攻め側の質感（支配的な笑い、命令口調、からかい）を
受け側・崩壊側に持ち込むと構図がおかしくなる。** 逆もまた然り。
キャラが「強キャラ・サド系・俺様系」だからといって、絶頂中にも
その態度を維持させると不自然になる（本人が平常運転できない
状況だから絶頂なわけで）。

例外: ふたなり/ペニバン使用で自分が挿入側に回るCOM（COM193-195、
COM65、COM204等）は絶頂中でも攻め側に留まる構図が成立する。
この場合のみ支配的な質感を維持してよい。設計段階でこの
切り分けを意識する。

===============================================================
■ 作業着手時の思考プロセス
===============================================================

4点アップロード（v3プロンプト・全セリフ集・ベースERB・COM.ERB）
を受け取ったら、**いきなりベースERBを書き始めない**。

まずv3プロンプトと全セリフ集を読み、以下を自分の言葉で
書き出してユーザーに確認を取る:

### 書き出すべき内容（堅苦しいシート形式は不要）

- **このキャラはどんな人か**（プロンプト要約ではなく、
  自分がつかんだ人物像を3〜5行で）
- **このキャラの身体性・職業性・精神性のうち、
  セリフの随所に滲み出すべき固有要素**
- **告白セリフに込めるべき葛藤**
  （多くのキャラは恋愛に何らかの障壁を持つ。
   それを具体的に言語化しないと、告白セリフが軽くなる）
- **独自枠（COM280-284/COM410-414）で何をやるか**
  （キャラ固有のシチュエーション）
- **このキャラの表現レンジ**（下記参照）
- **絶頂時の崩壊の仕方**
  （何が崩れると「このキャラが乱れた」と感じられるか。
   3軸と数を決めつけるより、「何が崩れ得るか」を広く持つ）

これをユーザーに提示して「この方向で進めるよ」と確認を取る。
ここでユーザーから修正が入れば、それを踏まえて書き始める。

### 表現レンジの設計

キャラを立ち上げる前に、**そのキャラがどんな音・表現を
持ち得るか**を広めに見積もっておく。これをやらずに書き始めると、
最初に掴んだ2〜3個の表現を全セリフで使い回すことになる。

確認すべき項目（例、キャラによって該当するものを選ぶ）:
- **一人称・二人称**: 公式モード・素・混濁時で変化するか
- **敬語/タメ口/方言の切替**: 相手との関係や状態で変わるか
- **口癖・語尾の傾向**: そのキャラの地の口癖・語尾癖は何か。
  ただし**全セリフに入れる必要はない**。使わないセリフも
  あっていい
- **笑い方の傾向**: そのキャラに似合う笑い方は何系か
  （軽い/上品/活発/歪み/無邪気/含み等）。笑わないキャラも
  存在する
- **喘ぎ音の傾向**: どの音が中心で、どれが混ざり、どれは
  使わないか（あ系/ん系/ふ系/ひ系/や系など）
- **感嘆詞・呼吸表現**: 擬音（ごふっ/ぷはっ/ひゅっ等）、
  長母音伸ばし、省略（……）、短文畳みかけ、どれが似合うか

**この見積もりが広ければ広いほど、後半のセクションで手癖に
流れずに済む。** 見積もり段階で「このキャラが絶対に使わない
表現」も言語化しておくと、書いている途中で前キャラのパターンが
混ざりかけた時に気づきやすい。

===============================================================
■ 書いているときに常に自問すること
===============================================================

### セクションを書き終えるごとに

- このセクションのセリフを、前キャラのセリフと並べたら、
  **誰が喋っているか一目でわかるか**？
- 同じコマンドに対する3バリエ（RAND:3）は、
  **それぞれ違う方向の反応か**？同じ気持ちを違う言い回しで
  書いただけになっていないか？
- 特徴的な表現（口癖・笑い方・喘ぎ音）が**連続で出すぎて
  いないか**？セクション全体で濃淡があるか？
- キャラ固有の要素が**全セリフに入っていないか**？
  （全部に入れると逆に薄まる。効くところで効かせる）
- 呼吸や切迫の表現手段が**単一のパターンに偏っていないか**？
  （句読点刻み一辺倒、長母音一辺倒、擬音一辺倒、いずれも
   単調になる。手段を混ぜる）

### 特に絶頂150箇所で

単部位絶頂ならその部位感覚に言及していい（「奥」「先っぽ」「そこ」）。
複部位・五重絶頂で「同時に」「複数箇所」と書き始めたら止める。
絶頂中の人間はシステム的自己言及をしない。

3バリエは反応の性質で差別化する。
「叫び/哀願/呼吸困難」のような固定3軸ではなく、
**そのキャラなら何が崩れるか**から導く。
キャラごとに崩れ方の質は全く違う。**次のキャラで同じ軸を
使うと「前キャラの流用」になる。**

絶頂のグラデーション（通常/強/最強）で、崩壊の深度と
表現の質を変える:
- **通常**: 強がりや照れ隠し、キャラの地の口調が保たれる
- **強**: 防衛線がほころび始める。素の言葉が混じる
- **最強**: 固有名詞の混濁、内的な言葉の崩壊、長母音主体

### ステップ2〜6: COM.ERBをセクション単位でマージ

| # | セクション | 箇所 | 累計% |
|---|---|---|---|
| 2 | 純愛コミュ COM300-325 | 196 | 21% |
| 3 | キス/ウフフ/特殊/独自枠 | 172 | 40% |
| 4 | えっち系メイン COM0-195 | 204 | 62% |
| 5 | その他+処女/FK/脱衣/射精 | 200 | 84% |
| 6 | 絶頂 | 150 | 100% |

区切りマーカー:
- ステップ2: `;--- COM300` → `;===...; キス系`
- ステップ3: `;===...; キス系` → `;===...; えっち系`
- ステップ4: `;===...; えっち系` → `;===...; その他コマンド`
- ステップ5: `;===...; その他コマンド` → `;===...; 絶頂したとき`
- ステップ6: `;===...; 絶頂したとき` → ファイル末尾

各ステップ終了時に必ず present_files で報告、20%刻みで
ユーザーに進捗確認させる。ユーザーから指摘があれば
その時点で軌道修正。

### マージ用Pythonテンプレ

```python
import subprocess
current = subprocess.run(['iconv', '-f', 'SHIFT-JIS', '-t', 'UTF-8',
    '/mnt/user-data/outputs/CHAR_XX_キャラ名_COM.ERB'],
    capture_output=True, text=True).stdout
with open('/home/claude/new_section.txt', 'r', encoding='utf-8') as f:
    new_section = f.read()
current = current.replace('\r\n', '\n')
new_section = new_section.replace('\r\n', '\n')
start_idx = current.find(start_marker)
end_idx = current.find(end_marker)
new_content = current[:start_idx] + new_section + current[end_idx:]
new_content = new_content.replace('\n', '\r\n')
with open('/mnt/user-data/outputs/CHAR_XX_キャラ名_COM.ERB', 'w',
    encoding='cp932', newline='') as f:
    f.write(new_content)
```

### 最低限の検証（各ステップ後）

```bash
grep -c 'PRINTFORMW' [file]          # 最終922
grep -c 'PRINTFORMW 「」' [file]      # 0 必達
grep -c '彼氏' [file]                  # 0 必達（v3プロンプトで例外指定ない限り）
```

数値チェックはあくまで機械的な整合性確認のみ。表現の質は
機械的なカウントでは測れない。特定表現の頻度を数値で縛ると
逆に多様性を失うので、**表現の質はユーザーからのフィードバックで
都度調整する**前提。

■ COM.ERB 構造メモ
===============================================================

### 922箇所の内訳
純愛コミュ196 / キス27 / ウフフ105 / 特殊告白36 / 独自枠4 /
えっち系メイン204 / その他コマンド122 / 処女FK脱衣6 /
射精3種72 / 絶頂150

### 主要な分岐パターン

**純愛コミュ系**: 初回フラグ→RAND:3×(恋人/親密[ABL>=6]/通常)

**成功/失敗分岐** (TFLAG:18 == -1 失敗): COM302/303/311/312/323/340/341/342/399 等

**その他コマンド（COM3-390）**: 恋人/通常各1行のみ

**射精3種**: 大量(TFLAG:302>=2)/通常 × 初回(TFLAG:711==1)/複数回 × 恋人/通常 × RAND:3

**絶頂**: TFLAG:710で同時絶頂数、NOWEX:0-6で部位・強度

===============================================================
■ 技術的な罠
===============================================================

### チルダは「〜」(U+301C) で統一
「～」(U+FF5E) ではない。str_replace や Python置換で
「～」を使うとマッチ失敗するので注意。

### Shift-JIS + CRLF 保存
```python
content = content.replace('\r\n', '\n').replace('\n', '\r\n')
with open(path, 'w', encoding='cp932', newline='') as f:
    f.write(content)
```

===============================================================
■ ユーザーから受けた指摘の傾向
===============================================================

これまでのフィードバックは、根っこを辿ると下記のどれかに収束する:

### 内容面の薄さ
- 絶頂セリフが説明的（システム概念への言及）
- RAND3パターンが似すぎ（違う言い回しで同じ反応）
- 職業・体質・人間関係の距離感が通常モードに表れていない
- 告白セリフの葛藤が薄い（キャラ固有の受けにくさを描く）

### キャラ間の混濁
- 前キャラ使い回し（コピペではないがパターンが同じ）
- 喘ぎ音・崩壊軸・3バリエの型が前キャラと同じ

### 表現の手癖化
- 特徴的な表現が1セリフに詰まりすぎて陳腐化する
  （何が手癖化するかはキャラによって違う）
- 呼吸の刻み方が単調（単一手段の多用）
- キャラの状態とセリフの質感のミスマッチ
  （攻めの質感を受け側に持ち込む等）

**全部、根っこは同じ**: Claudeが作業の途中で省エネに流れる、
あるいは最初に掴んだ数個のパターンで全体を書こうとする。

対策も一つ: **書き終えたセクションを眺めて、キャラが立ち
上がっているかを自分で確認し、立ち上がっていない箇所を
書き直す**。この工程をサボらない。
